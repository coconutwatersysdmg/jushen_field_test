巨神智能 · 现场离线联调（独立项目）
========================================
目录：本仓库根目录 jushen_field_test

当前现场雷达测试
----------------
运行 main.py 或双击「启动软件.bat」，控制台会持续输出 [RADAR_SYNC] 监视日志。
雷达工控机 wave 文件夹的文件同步到本项目「存itl」文件夹，每 10 秒扫描一次。
同步不限文件类型，仅拷贝 2026-10-01 00:00 起（含当天）的文件，较新的优先。
日期优先取文件名里的采集日期（yyyy-MM-dd），无有效日期时使用文件修改时间。
本地已有同名文件直接跳过，不因大小或修改时间不同而覆盖；日志统计日期之前跳过的数量。
PCD 拷贝完成后才以正式文件名出现；拷贝失败会输出原因，下次扫描重试。
「存itl」保存工控机同步的原始文件；「PCD」保存用于算法的 PCD 点云。
点击「选择 PCD」，默认打开「PCD」；选好后点击「运行雷达算法」。
项目启动后自动监视「存itl」：ITL 文件稳定 2 秒且无写入占用后，转换为「PCD/原文件名.pcd」。
转换不依赖 EXE 或雷达网络；已完成文件不会重复转换，源文件更新后会重转，失败会输出日志并重试。
转换标定参数：config/itl_conversion.ini；格式和样本校验说明：docs/itl_conversion.md。
取消选择就停在原地，后台同步继续；当前不运行相机、插孔、放货流程。
所有监视输出同时保存在 logs/startup.log；关闭程序会停止本次同步进程。
监听启动失败、共享不可达或监听进程退出，只输出日志，不弹窗、不阻止本地 PCD 选择和算法运行。
同步脚本只尝试访问当前网络上的共享，不切换网卡、不修改 IP 或路由。
恢复完整现场流程：将 config/feature_switches.py 的 RADAR_ONLY_TEST 改为 False。

现场作业工作区（第一阶段：只联调，不接真机、不调算法）
----------------
现场模式（顶部「模式」选「现场离线联调」）下：
- 顶部只有一条「现场作业流程」，默认收起，点标题展开。它按两条业务线显示真实进度：
  A 每车一次：雷达现场扫描 → 点云处理/四角 P1~P4 → 结果回传 PLC → 海康按坐标拍照/角点精定位；
  B 每车十余次：拍托盘/插孔识别 → 叉车插取放货 → 放后再拍/动态监测 → 未达计划件数→下一轮。
  实验室四步条、选择 PCD、检查离线路径、执行下一步等按钮在现场模式下不再显示。
- 中间图形视图维持原样，默认仍是数字孪生；点中间 tab「角点作业」「托盘循环」进入现场工作区。
角点作业：从雷达粗结果取 P1~P4（没有结果时可点「用演示坐标」）→ 导出拍照指令 JSON
（target=PLC，status=INTERFACE_PENDING，接口文件到位后改为直接下发）→ 选/用示例角点照片
→ 算法槽载入结果 JSON → 导出本车结果。
托盘循环：轮次按 data/loading_plan.json 每条货物的 quantity 展开。每轮依次是拍托盘照、
载入插孔结果、确认插取放货、放后再拍、载入动态监测结果、完成本轮；轮次自动前进。
算法槽不调用模型，只能手动载入 examples/module_outputs 下的结果 JSON 做界面联调，
界面和导出的 JSON 都标明结果来源，不会把联调结果当成真值。
归档目录：workdir/field_runs/<日期>/<车号>/<工作区>_<时间戳>/，含 images/、json/、
manifest.json；界面底部显示当前目录并可一键打开。车号可直接在底部输入。
现场大字号：启动软件.bat 与 启动软件_调试模式.bat 已默认启用 field 主题，直接双击即可；
如需临时切回旧字号，把 bat 里的 set "JUSHEN_UI_THEME=field" 这一行删掉。

五、目录清理
  关闭软件后，可清理历史输出 outputs/、临时文件 tmp/、转换器试验 workdir/converter_probe/、
  logs/ 以及项目自身的 __pycache__/。清理会删除相应历史结果，不影响正常运行。
  保留 .venv/、源码、config/、models/、算法 checkpoints/ 和 third_party/。
  保留 PCD/、存itl/ 中的输入数据，以及 workdir/ 中的状态、设置和数据库，勿整目录删除 workdir/。
  GitHub 备份保存源码、配置、模型和随项目附带的运行库；运行环境需按安装说明重建，采集数据另行保管。
  outputs/、tmp/、日志、Python 缓存和 node_modules/ 已加入 .gitignore。

六、NVIDIA 显卡加速
  安装基础环境后，关闭软件，双击「安装显卡加速.bat」安装并验证官方 CUDA 13.0 版 PyTorch。
  日常仍使用「启动软件.bat」；GPU 可用时自动用于 PointNet++ 推理，无可用 GPU 时使用 CPU。
  模型权重、点云点数、全点覆盖策略和几何参数保持不变；GPU 推理关闭 TF32，保留 FP32 计算。
  计算结果 timing.pointnet.device 会记录实际使用的 cpu 或 cuda。
  显卡运行库比 CPU 版占用更多磁盘空间；地面拟合及角点几何后处理仍在 CPU 上执行。
  本机显卡切换验证（2026-11-22，叠加整车−1°旋转前，RTX 5070 Laptop，同一份 519 万点 PCD）：
  CPU 总流程 37.59 秒，GPU 总流程 30.47 秒；模型分割 16.18 秒降至 9.27 秒。
  该样本的分割标签和全部 8 个角点最终坐标一致；实际耗时随点云和电脑负载变化。

七、提取后的整车点云旋转
  先按原流程预处理并用 PointNet++ 提取/分割卡车，再将整车点云绕雷达原点的 Z 轴旋转−1°。
  旋转后的点云与原分割标签一起进入边界、分界线、高度和角点几何计算，随后输出角点。
  XY 同步旋转，Z 不变；原始 PCD 文件不改写，每次重新读取后只应用一次旋转。
  此定义与既有人工补偿点云对比记录一致：WORLD 中以 (13939, 7715) mm 为中心旋转−1°。
  原有雷达转 WORLD 的−90.7°与平移保持原定义，整车校正单独记录，不额外再次旋转输出角点。
  配置位于 config/system_config.py 的 point_cloud.truck_rotation_z_deg；设为 0 可关闭。
  结果 JSON 的 truck_rotation 记录旋转轴、角度、中心和处理位置；XYZ独立拟合补偿属于另一阶段。
