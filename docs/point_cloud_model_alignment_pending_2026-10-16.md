## 已澄清的输入模式与后续实施约束

1. 当前调整目标是软件的部署输入和推理流程，采用“每次49152点，多次覆盖整车全部点”。本轮仍然仅记录，不开始重训或替换权重。
2. 每个待分类原始点至少直接参与一次网络前向，并取得自身预测；记录原始点编号和覆盖次数，输出前确认无遗漏。按编号将自身预测放回原始点序不属于最近邻标签映射。
3. 每次输入从整车范围组织，保持整车上下文，不把车辆沿车长硬切成若干局部空间块。组织点组时兼顾包内体素均匀采样方式与全点覆盖；固定种子确保同文件重复推理可复现。
4. 包内加载器先在完整点云上计算归一化，再按索引取49152点。后续多次覆盖必须共享同一完整点云的归一化参数，不对每一组独立重新归一化。
5. 最后一组不足49152点时，从同车点云补齐；不足49152点的小点云也按包内思路重复采样补齐。重复点的预测融合方式在实现方案中明确，仅融合该原始点实际取得的多次预测，不推断未入网点的标签。
6. “覆盖全部点”相对于训练加载器的单次抽样增加了覆盖调度约束。输入点数与归一化可以对齐，但不能未经实验就称每组采样统计分布完全相同，或预先保证精度提升；需要在既有单板、双板问题文件上验证。
7. 覆盖对象沿用现有预处理后的完整卡车点云，不依赖未知的底板真值提前筛点，也不额外删除训练时存在的挡板、轮胎等上下文。“全点”指模型入口保留的全部点，不是恢复已在ROI、体素或滤波阶段移除的点。

## 后续讨论：二维角点还原为三维时没有对应扫描点

用户提出该问题很关键。本轮仅核对现有逻辑和记录讨论方向，未修改几何算法。

- 现有流程：底板平面拟合 → 建立平面局部UVN坐标系 → 丢弃法向N分量得到UV → 四边直线拟合求交 → `P=C+u*U+v*V` 构造雷达三维角点 → 转换到世界坐标。
- `uv_to_3d` 不查询原始点，也不要求角点与某个扫描点重合；即使该位置没有点，仍会输出拟合平面上的交点。这是根据几何模型估计角点，不是恢复被丢弃的每个原始点法向残差，也不是只把全局Z补成0。
- 现有代码有平面/直线最少内点数量及求交矩阵行列式检查，但没有针对每个角点检查邻近边缘支撑、到有效边段的外推距离、局部平面一致性等。局部角点缺测与远距离无支撑外推目前没有单独区分。
- 拟议改进方向（尚未实施）：保留连续几何交点；为角点记录相邻两条边的支撑范围、外推长度、局部残差/点距及可靠性；支撑不足时明确标记不可靠。不要仅因不存在同坐标扫描点就判错，也不要未经检查将角点吸附到最近扫描点。
- 具体阈值应依据扫描间距、局部缺测和工程容差验证，不在讨论阶段指定未经验证的固定数值。

### 用户进一步关注：长底板局部高度与全局平面不一致

- 用户认为XY边线交点有充分支撑，担心长底板的上翘、下倾或局部起伏不能由单一全局平面准确表示，希望三维角点利用原始点自身的几何信息。
- 已核对代码：`project_points_to_uvn` 本可返回每个点的法向残差N，但实际调用 `u,v,_` 将其丢弃；`uv_to_3d` 仅计算 `C+uU+vV`，相当于所有角点取N=0。现有还原并不恢复各原始点的高度偏差。
- 单纯整体倾斜的平板能够由斜平面表示；不能仅凭底板长度就断言拟合必然变差。局部翘曲、弯曲，以及噪声/错分造成的全局平面偏差才需要单独诊断。
- 对原扫描点，保存原始索引和完整UVN即可还原其原始XYZ；对新求出的UV角点，没有天然对应的原始N，仍需根据周围真实三维板面估计，不能宣称恢复出某个不存在扫描点的真实高度。
- 拟议方向，尚未实施：全局平面保留为二维边缘处理参考；角点高度回到分割后的原始三维底板点，依据各角点附近、同板上表面局部点做稳健平面拟合，必要时再验证低阶曲面。若XY确定且要求保持不变，在固定XY处计算局部 `Z=f(X,Y)`，不将角点吸附到最近点。
- 局部高度估计不能仅使用全局RANSAC内点，否则偏离全局平面的真实翘曲板面可能已被删除。仍须排除侧板、竖直台阶和漂浮点；不能为“全点利用”放弃几何污染检查。
- 法向残差修正 `P=C+uU+vV+n_hat*N` 在参考平面倾斜时可能同时改变全局XYZ，不等价于固定XY只修正Z；后续设计需明确选择，不混淆两者。
- 后续验证应同时输出原全局平面Z、局部估计Z、高度差和局部支撑质量；目前未证明局部方法在所有现场样本上更准确。
