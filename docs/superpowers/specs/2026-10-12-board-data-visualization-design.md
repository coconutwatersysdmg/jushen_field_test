# 板面数据可视化设计

## 目标

在主界面中心标签栏新增“板面数据”页面，集中显示两块板的雷达车板数据和相机装载区域数据。操作员可以直接比较两种算法的五项输出，同时通过点击指标名称查看计算公式。

本次改动保留主界面现有角点 WORLD 坐标表。新页面不重复显示角点坐标，也不改变现有数字孪生、雷达预览和相机预览页面。

## 已确认的界面要求

- 中心标签栏新增“板面数据”，与“数字孪生”“实时雷达”“本流程相机”并列。
- 页面固定展示“第一块板”和“第二块板”两个数据区域。
- 每块板只展示两行数据：
  - 雷达车板数据
  - 相机装载区域数据
- 每行展示五项指标：
  - 长度
  - 宽度
  - 平均高度
  - 纵向倾斜角
  - 水平偏移角
- 删除以下内容：
  - “雷达 P1–P4 · 相机装载区 P1–P4”等角点范围说明
  - 雷达和相机颜色图例
  - “查看第一块板角点坐标”和“查看第二块板角点坐标”链接
  - “用途”列
  - “粗定位参考”“最终划格”“允许划格”等用途或状态文字
- 角点坐标继续由主界面现有角点 WORLD 表显示。

## 指标公式交互

五个指标名称显示为可点击表头，文字后附信息标记。点击后打开一个小型说明窗口。窗口包含指标定义、公式、单位和正负号说明。

### 长度

```text
L = [d(P1,P3) + d(P2,P4)] / 2
```

分别计算左右两条纵向边的三维长度并取平均值，单位为毫米。

### 宽度

```text
W = [d(P1,P2) + d(P3,P4)] / 2
```

分别计算前后两条横向边的三维长度并取平均值，单位为毫米。

### 平均高度

```text
H = (z1 + z2 + z3 + z4) / 4
```

计算四个角点 Z 坐标的算术平均值，单位为毫米。

### 纵向倾斜角

```text
C_head = (P1 + P2) / 2
C_tail = (P3 + P4) / 2
Delta = C_tail - C_head = (dx, dy, dz)
tilt = atan2(dz, sqrt(dx^2 + dy^2)) * 180 / pi
```

角度为正表示车尾端高于车头端，角度为负表示车尾端低于车头端，单位为度。

### 水平偏移角

```text
offset = atan2(dx, -dy) * 180 / pi
```

当前坐标系的负 Y 方向为零度基准。向正 X 方向偏转为正，向负 X 方向偏转为负，单位为度。

## 数据结构和计算规则

雷达与相机使用相同的五项几何公式，但输入对象不同：

- 雷达输入为实际车板四角，输出名称为“雷达车板数据”。
- 相机输入为装载区域四角，输出名称为“相机装载区域数据”。

雷达数据优先读取 `radar_result.boards` 中每块板已经计算完成的五项指标。第一块板对应第一组雷达板面结果，第二块板对应第二组雷达板面结果。

相机数据只允许从真实的 `camera_world_corners` 计算，不使用雷达兜底角点冒充相机数据。角点分组规则如下：

- 8 点结果：第一块板使用 P1、P2、P3、P4；第二块板使用 P5、P6、P7、P8。
- 6 点压缩结果：第一块板使用 P1、P2、P3、P4；第二块板使用 P3、P4、P5、P6。
- 4 点结果：只生成第一块板相机数据，第二块板显示空值。

如果某一来源没有完整的四个 WORLD 角点，该来源对应的五项指标全部显示短横线，不用其他来源补齐。这样可以保证界面显示的数据来源真实明确。

相机内部已有的 `yaw_deg` 保持不变，继续供现有规划逻辑使用。板面数据页面新增的水平偏移角严格使用与雷达相同的负 Y 基准公式，并单独输出为 `offset_angle_deg`。

## 界面组件

新增共享组件 `BoardDataPanel`，供当前主窗口和保留的完整主窗口复用，避免两份界面代码产生差异。组件包含：

- 页面标题“车板与装载区域数据”
- 第一块板数据表
- 第二块板数据表
- 五个可点击指标表头
- 五个公式说明弹窗

每块板的数据表包含六列：数据来源、长度、宽度、平均高度、纵向倾斜角、水平偏移角。数值格式为：

- 长度、宽度、平均高度保留 3 位小数并显示 `mm`
- 纵向倾斜角、水平偏移角保留 6 位小数并显示 `°`
- 无效或缺失数据统一显示 `—`

## 刷新流程

主窗口每次收到新的数字孪生快照或轮次数据时，刷新板面数据页面：

1. 从 `round_data.radar_result.boards` 提取两块雷达板面结果。
2. 从 `round_data.lab_corner_shell.camera_world_corners` 或 `round_data.camera_world_corners` 提取纯相机 WORLD 角点。
3. 按 8 点、6 点或 4 点规则分组。
4. 对每组四点调用统一几何计算函数。
5. 更新两块板的雷达行和相机行。

切换到“板面数据”标签时只显示已经缓存的数据，不重新运行雷达或相机算法。

## 异常处理

- 雷达算法未运行或没有板面结果时，雷达行显示短横线。
- 相机只输出像素坐标、没有 WORLD 坐标时，相机行显示短横线。
- 相机角点数量不足或坐标值无效时，只清空对应板面，不影响另一块板显示。
- 公式弹窗不依赖算法结果，任何时候都可以打开。
- 界面刷新不得修改雷达结果、相机结果、划格结果或 PLC 数据。

## 测试范围

- 验证 8 点、6 点和 4 点相机角点分组。
- 验证相机五项数据与雷达公式一致，尤其是水平偏移角使用负 Y 基准。
- 验证雷达两块板正确映射到第一块板和第二块板。
- 验证缺失相机 WORLD 坐标时不使用雷达数据填充相机行。
- 验证主窗口新增“板面数据”标签，并且切换后显示新页面。
- 验证五个指标表头均可打开对应公式说明。
- 运行现有自动化测试和启动冒烟测试，确认数字孪生、雷达预览、相机预览及现场流程不受影响。

## 不在本次范围内

- 不调整现有角点编号。
- 不移动或删除主界面的角点 WORLD 坐标表。
- 不修改最终划格使用哪一组角点的业务决策。
- 不把雷达角点标记为相机角点。
- 不新增相机像素坐标到 WORLD 坐标的标定或转换算法。
