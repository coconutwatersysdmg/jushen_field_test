网络 1：【TCP 协议说明】
1、不能在连接保持 CONT=1 时，对通讯长度进行修改，会造成通讯错位，重启 CPU 有效，可以清空缓存区
2、TSEND_C 状态是 BUSY，可能是接收端异常
3、TSEND_C 的 REQ 用上升沿触发，TRECV_C 一直接收 TRUE
4、CONNECT 的 DB 块是在属性-配置中-连接类型-新建的。属性配置完毕后，DB 块自动生成起始值。
5、TSEND_C 和 TRECV_C 的 CONNECT，可以一致。也就是说，配置好一个，可以直接复制到另一个中。
6、CONNECT 中的 ID 意义不大，别重复就行。一组连接（DB 块一样）的 TSEND_C 和 TRECV_C 的可以一致。
7、只在被动连接的 CPU 设置端口号，建议从 2000 开始，2000 以下不能乱用。而且要在硬件网络中双方 CPU 都配置端口号。
8、硬件网络中，即使是单边通讯（未指定），也需要在两个 CPU 上都设置一次 TCP 连接，区别于 PUT/GET 只在主动连接的 CPU 设置一次即可。
9、硬件在线时，在网络中可以看到 TCP 连接是否成功，也可以看到当前已编程开放式通讯是否成功。只有两侧 CPU 都成功时，才可。
10、有时有连接记忆的时候，可以通过 STOP 或者重新下载硬件的方式试试。
11、实在不行，就 STOP 试试。有一次发送端一直 BUSY，改 CONT 口也不好使，就把接收端 CPU 给 STOP 立马好了。很神奇。
